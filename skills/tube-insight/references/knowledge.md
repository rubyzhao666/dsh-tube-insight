# Knowledge：知识卡片 / 知识库导出

> **何时读我**：用户说「整理成知识卡片」「导出到 Obsidian / Notion / 知识库」「把这条视频的收获沉淀下来」「帮我把概览 + 情报 + 洞察合成一篇笔记」，或要把已有多份分析合并成一份可长期保存的 Markdown。
>
> **移植自**：TubeInsight `prompts/knowledge-export.prompt.js`（知识库导出）。原版把各模块输出拼进提示词让 DeepSeek 整合；这里改成**你自己整合已产出的内容**。卡片结构、methodology 分支、空模块规则原样保留。

## 前置

知识卡片是**整合**，不是重新分析。先把需要的模块准备好：

| 模块 | 来源 | 是否必需 |
|---|---|---|
| 视频基本信息（标题 / URL / 日期 / 标签） | `tube_transcript` 返回 | 必需 |
| 内容摘要 / 核心价值 | `references/overview.md` 的产出，或现场快速生成 | 必需 |
| 产品情报 / 核心方法论 | `references/intel.md` 的产出 | 有就整合 |
| 关键洞察 / 技术边界 | `references/insights.md` 的产出 | 有就整合 |
| PRD 草稿要点 | `references/prd.md` 的产出 | 有就整合 |
| 我的笔记 | 用户提供的笔记原文 | 有就原样保留 |

没有现成产出的模块：要么按对应 reference 现做一遍，要么在卡片里标「（本次未生成）」。不要用一句「暂无」糊过去。

## 分支规则

- **`content_type=methodology` 时**：把「🔍 产品情报」整章换成「🧭 核心方法论」，下设四个小节：核心方法论（`core_methodologies`）、关键原则（`key_principles`）、可迁移场景（`application_scenarios`）、方法论关键词（`methodology_keywords`）。
- **有技术边界时**：在「💡 关键洞察」末尾加「技术边界」小节，每条写技术名称、已实现能力、当前边界。
- **某个模块为空**：对应章节标注「（本次未生成）」，不要删掉章节结构。
- **用户笔记**：原样保留在「我的笔记」，这是用户的原始记录；导出时把原文传给 `tube_export` 的 `notes` 参数，不要传你改过的版本。**注意**：工具会把 `notes` 追加成新的「## 我的笔记」章节，正文里已经写了这一章就不要再传 `notes`，否则会重复。
- **去重**：产品情报、洞察、PRD 里重复出现的结论只保留信息量最大的一处，卡片要的是密度不是篇幅。
- **标签**：从内容提炼 2–3 个，格式 `#标签名`；不要用 #视频 #学习 这种没有信息量的泛标签。
- **下一步行动**：必须具体可执行，并且能回到视频内容；不要写「多看看相关视频」。

## 引用规则

- 摘要、功能、痛点、洞察、PRD 要点里每条结论都带 `[MM:SS](https://youtu.be/<videoId>?t=<sec>)`。
- 用户笔记部分不强行加引用；用户要求时才补。
- 一张卡片只对应一个视频时，所有链接都用这个 `videoId`；多视频合卡时，每个条目用各自视频的 id，并在标题下补充「来源视频」列表。

## 存档

用户要保存时调 `tube_export`：`module=knowledge`，`videos=[视频来源]`，`markdown=本卡片正文`，`notes=用户原始笔记`。工具会补 frontmatter 和来源区块，正文里不用自己写。

## 交付前自查

- 六个以上章节结构齐全吗？空模块标了「（本次未生成）」吗？
- 摘要是否 ≤300 字、信息密度够不够（有没有来回重复）？
- 每条关键内容都有可跳转出处吗？
- methodology 类型是否换成了「核心方法论」分支？
- 标签是否具体？下一步行动是否可执行？
- 用户笔记是否原样保留、没有被改写？
