# PRD：把视频内容转成 PRD 草稿

> **何时读我**：用户说「把这条视频做成 PRD」「从视频里出一个产品方案 / 需求文档」「这条视频的产品点能不能落地成功能」。用户要完整 PRD 流水线（prd.json、验收清单、流程图）时，也先按本文件产出草稿，再交给可用的 PRD 工具。
>
> **移植自**：TubeInsight `prompts/prd-generator.prompt.js`（PRD 素材生成器）。原版把字幕 + 产品情报喂给 DeepSeek 生成 Markdown；这里改成**你自己生成**。六章模板、优先级规则、方法论转产品构想的规则原样保留。

## 前置

1. 已 `read` 读完 `transcriptPath` 全文。
2. 已按 `references/intel.md` 做过产品情报判断，得到 `content_type`（product / methodology）和情报字段。判断结果放在「已提炼的产品情报（参考）」里作为写 PRD 的输入。
3. `content_type=methodology` 时，视频本身不是在讲产品：把 `core_methodologies` 转成一个**可落地的产品构想**来写 PRD，并在「背景与目标」开头注明「本 PRD 基于视频中的方法论进行产品化构想」。

## 输出模板（六章，不能少章）

```markdown
# PRD 草稿：{视频主题}

> 来源视频：{视频标题} — {https://youtu.be/<videoId>}
> 内容类型：product / methodology（methodology 时下面这句要保留）
> 本 PRD 基于视频中的方法论进行产品化构想

## 一、背景与目标

{描述产品背景、市场机会、要解决的核心问题，3–5 句。有视频依据的句子后面带 [MM:SS](链接)；属于推演的结论标「（推断）」。}

## 二、目标用户

| 用户类型 | 特征描述 | 核心诉求 |
|---|---|---|
| 主要用户 | …… | …… |
| 次要用户 | …… | …… |

## 三、用户故事

1. 作为【用户角色】，我希望【做某事】，以便【获得某种价值】
2. 作为【用户角色】，我希望【做某事】，以便【获得某种价值】
3. 作为【用户角色】，我希望【做某事】，以便【获得某种价值】

（先判断视频能支撑的用户角色，不要求固定 3 条；每条都可以在功能表里找到落点。）

## 四、核心功能列表

| 优先级 | 功能名称 | 功能描述 | 预期效果 | 视频依据 |
|---|---|---|---|---|

## 五、验收标准

- [ ] {具体可测量、有明确通过条件}
- [ ] {……}
- [ ] {……}

## 六、待确认问题

1. {需要进一步调研或决策的事项}
2. {……}
3. {……}

> 本文档由 DSH `tube-insight` skill 基于视频内容生成，仅供参考，请结合实际业务需求修改完善。
```

## 写作规则

- **优先级**：P0 = 必须有，P1 = 重要，P2 = 锦上添花。不要把视频里所有点都塞成 P0。
- **用户故事**必须符合标准格式「作为…我希望…以便…」，不要写成功能描述。
- **验收标准**要具体可测量：「生成的报告里每条结论都有时间戳且可跳转」可以，「体验良好」不行。
- **信息不足**：某章视频内容撑不起来时，写「（信息不足，需补充）」，不要编。
- **视频依据列**：核心功能表里每条功能给一个来自视频的 `[MM:SS](链接)`；如果这个功能是你的推演，写「（推断）」并说明从视频哪段推出来。
- 语言默认中文；要英文/双语按 `references/translation.md`。
- 不要在 PRD 里替用户做技术选型结论（可写「技术考虑」类建议，但要标推断）。

## 与 prd-generator 的关系（可选联动）

如果当前会话里同时装了 `prd-generator` skill（插件 `dsh-prd-generator`，提供 `prd_write` / `prd_check` 工具），并且用户要的是**完整 PRD 流水线**（`prd.md` + `prd.json` + 验收清单 + 流程图）：

1. 先按本文件产出并确认这份 PRD 草稿；
2. 把草稿内容整理成 `prd-generator` 要求的 `prd` 对象（name / summary / user_stories / features / acceptance 等），再调用它的工具落盘、校验。

没有安装该插件时，**不要提这些工具名、也不要假装能生成 `prd.json`**，只交付本文件的 Markdown 草稿。

## 存档

用户要保存时调 `tube_export`，`module=prd`，`videos=[视频来源]`，`markdown=这份 PRD 正文`。工具会补 frontmatter 和来源区块，正文里不用自己写。

## 交付前自查

- 六章齐全吗？缺的章是否标了「（信息不足，需补充）」？
- 功能表每条有优先级、有视频依据吗？P0 是否克制？
- 用户故事是标准句式吗？验收标准是否可测量？
- methodology 类型时，是否在背景开头注明了「基于方法论进行产品化构想」？
- 视频没说的内容有没有被写成事实（而不是推断）？
