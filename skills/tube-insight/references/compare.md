# Compare：多视频横向对比

> **何时读我**：用户给 2–10 条 YouTube 视频，问「对比一下」「有什么共同点/差异」「竞品视频怎么讲」「这几条视频合起来说明什么趋势」。
>
> **移植自**：TubeInsight `prompts/multi-video-compare.prompt.js`（多视频对比分析）。原版把多个视频的摘要 JSON 数组喂给 DeepSeek；这里改成**你自己逐个视频提炼、最后汇总**。六节报告模板和「未提及」规则原样保留，并补上每个单元格的出处链接。

## 视频数量

- 少于 2 个视频：不要做对比，提示「至少需要 2 个视频才能对比分析」；单个视频改用 `references/overview.md` 或对应模式。
- 2–10 个：正常对比。超过 10 个先分批抓取分析，导出时按主题拆成多份。

## 数据准备（关键，决定质量）

不要把所有视频的全文同时塞进上下文硬比。按这个顺序做：

1. 逐个调 `tube_transcript`，拿到 `videoId` / 标题 / 频道 / 时长 / `transcriptPath`；
2. 逐个 `read` 全文，**每读完一个就写下一份对比用摘要**（可以先记在草稿里）；
3. 每份摘要至少包含：`one_line_summary`、`content_type`（product / methodology）、核心功能或核心方法论、用户痛点、技术方案、商业模式关键词，以及 **3 个左右带时间戳的支撑证据**；
4. 全部摘要齐了再横向对比。对比时只引用摘要和证据，需要更精确的措辞再回读对应片段。

对比用摘要的数据形状（保留上游契约，字段名一致，方便你要机读输出时直接给）：

```json
[
  {
    "title": "视频标题",
    "videoId": "xxxxxxxxxxx",
    "summary": "一句话核心内容",
    "content_type": "product | methodology",
    "product_features": ["…"],
    "user_pain_points": ["…"],
    "business_model_keywords": ["…"],
    "core_methodologies": ["…"]
  }
]
```

`content_type=methodology` 的视频重点比 `core_methodologies`，不要硬填功能点。

## 引用与判断规则

- 对比表里**每个来自视频的单元格**至少给一处 `[MM:SS](https://youtu.be/<videoId>?t=<sec>)`；同一格引用多个视频时，用对应视频 id 的链接。
- 每个视频用各自的 `<videoId>` 拼链接，**不要把 A 视频的时间戳挂到 B 视频的链接上**。
- 「共同趋势」必须有 ≥2 个视频的证据，只有一条视频说的不算共同趋势。
- 「差异化亮点」是相对其他视频的差异，不是把功能再列一遍。
- 「行动建议」要具体可执行，写清基于哪几条视频；不要写「持续关注行业动态」这种空话。
- 推断性结论标「（推断）」，与视频事实分开。
- 语言默认中文；英文/双语按 `references/translation.md`。

## 存档

用户要保存时调 `tube_export`：`module=compare`，`videos` 传**全部参与对比的视频**（≤10），`markdown` 传本报告正文。文末「来源」区块会逐个列出这些视频。

## 交付前自查

- 六个章节齐全吗？视频清单、概览表、对比矩阵是否覆盖全部视频？
- 每个单元格的结论都能点回对应视频的具体时间吗？视频 id 有没有串？
- 共同趋势是否至少有 2 个视频同时支持？
- 「未提及」是否如实写了，而不是被我补成了常识？
- 行动建议是否具体到能直接做？
