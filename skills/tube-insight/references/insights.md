# Insights：行业洞察（术语 + 观点 + 技术边界）

> **何时读我**：用户说「行业洞察」「这条视频里的专业术语是什么意思」「谁说了什么观点」「AI 产品经理能学到什么」「这项技术现在能做什么、边界在哪」。
>
> **移植自**：TubeInsight `prompts/insight-extractor.prompt.js`（行业洞察 & 观点提炼）。原版让外部 LLM 返回四段固定 JSON；这里改成**你自己提炼并输出**。字段与数量上限原样保留，`timestamp_hint` 升级成真实时间戳。

## 前置

已用 `read` 读完 `transcriptPath` 全文。术语和观点散落在全片，读半截必然漏。

## 任务

1. **行业术语识别与解释**：找出 AI / 科技 / 产品领域的专业术语，给简明中文解释。
2. **核心观点提炼**：梳理各发言人（或视频作者）真正表达的观点，按「谁 → 说了什么」组织。
3. **技术边界**：人物提到的技术现在能做到什么、怎么实现的、当前局限在哪、他认为何时/如何突破。**必须来自视频里人物的实际讲述，不要补充视频之外的技术常识。** 视频没讨论就给空数组。

## JSON 契约

```json
{
  "terms": [
    {
      "term": "术语名称（保留原文）",
      "explanation": "一句话中文解释（30 字以内）",
      "category": "AI模型/产品方法论/商业概念/技术架构/其他",
      "timestamp": "02:14",
      "timestampSeconds": 134
    }
  ],
  "key_insights": [
    {
      "speaker": "发言人名称或「视频作者」",
      "insight": "核心观点（一句话，50 字以内）",
      "quote": "原文中最能代表该观点的一句话（可选，如无则为空字符串）",
      "timestamp_hint": "[12:30]（中段）",
      "timestampSeconds": 750
    }
  ],
  "pm_relevance": [
    "与产品经理工作最相关的洞察 1",
    "与产品经理工作最相关的洞察 2",
    "与产品经理工作最相关的洞察 3"
  ],
  "tech_boundaries": [
    {
      "topic": "技术或能力名称（保留原文）",
      "speaker": "提到该技术的发言人名称或「视频作者」",
      "current_capability": "目前已经能实现什么、如何实现（一句话，60 字以内）",
      "boundary": "当前的局限或技术边界（一句话，60 字以内）",
      "outlook": "发言人对突破边界的判断或方向（一句话，如未提及则为空字符串）",
      "timestamp": "18:05",
      "timestampSeconds": 1085
    }
  ]
}
```

数量与格式：

- `terms` 最多 10 个最重要的，术语名保留原文（中英均可），解释用中文、约 30 字；
- `key_insights` 最多 8 条，每条一个观点，不合并多个意思；
- `pm_relevance` **固定 3 条**，专门筛对 AI 产品经理最有价值的内容；
- `tech_boundaries` 最多 5 条，没有就 `[]`；
- 用户要机读时输出合法 JSON（无围栏、无注释）。

## 真实性规则

- **观点必须来自视频**；引用的 `quote` 尽量给原文，并带时间戳链接。
- 术语解释可以结合通用知识，但如果视频里给了自己的定义，优先用视频里的说法；用常识补充时标「（背景补充）」。
- 不要因为「这个技术我了解」就补出一段视频没说的技术判断。
- 同一发言人多次表达同一观点时合并成一条，不要重复凑数。
- `pm_relevance` 是筛选与提炼，不是新观点——必须能从视频内容推回来。

## 交付前自查

- 每条观点都有发言人和时间戳吗？`quote` 是否真在转录里？
- terms 是否 ≤10、解释是否 ≤30 字左右、分类是否落在给定枚举里？
- pm_relevance 是否恰好 3 条？
- tech_boundaries 是否全部来自视频实际讲述？没有讨论时是否给了空数组而不是编内容？
