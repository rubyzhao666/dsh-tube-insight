# Recall：回忆 / 检索 / 主题综述

> **何时读我**：用户指的是**以前抓过、看过**的视频，而不是贴一条新链接给你。典型说法：「我以前看过的视频里，关于 X 都是怎么说的」「我记得有个视频说……帮我找出来」「把我看过的视频里关于 X 的观点汇总一下」「搜一下我的视频库/我抓过的视频」「做了这么久研究，帮我把 XX 主题整理成一篇综述」。
>
> **上游来源**：0.2.0 新增，无上游对应；0.3.0 加入 `tube_synthesis` 底稿。工具契约见 0.2.0 功能契约 F1（`tube_search`）与 0.3.0 功能契约 G1（`tube_synthesis`），签名已冻结；契约文档在插件开发仓库，不在本 skill 目录内。

## 先分清三种意图

| 用户说的 | 你要做的 |
|---|---|
| 「我记得有个视频说……」想找回**某一条视频** | 检索定位视频 → 给视频卡片（标题/频道/时长/链接 + 命中片段），确认是不是它；要找的是视频本身，别急着写综述 |
| 「看过的视频里关于 X 怎么说」要**快速观点汇总** | `tube_search` → 按视频/按观点组织 → 带双引用的综述（第 1–4 步） |
| 「把看过的视频整理成文章 / 主题综述 / 存成文章 / 发出去」要**成稿或存档** | 先 `tube_synthesis` 拿证据底稿（可落盘）→ 基于底稿写综述 → 要更完整的成稿再 `tube_export`（见第 3.5 步） |
| 贴了新链接、或要分析一条指定视频 | 不走检索，回到 SKILL.md 的四步工作流（overview / intel / insights 等） |

## 第一步：把用户的话变成检索词

`tube_search` 的 `query` 是关键词检索（BM25 + 连续短语加成），不是语义搜索。**口语要翻译成视频里可能出现的词**：

- 去掉口语外壳：「我记得/有个视频/以前/好像/帮我找找」不是检索词；
- 抽实体 + 术语 + 动作：人名、产品名、缩写、主题词；
- 一次 2–5 个关键词，最多 200 字符；不要整句丢进去（query 越长，词越稀释）；
- **视频里怎么说就怎么搜**：视频是英文就搜英文，是中文就搜中文；用视频里可能的原话短语（连续短语有加成）；
- 缩写与全称都试：`LLM` / `large language model`、`RAG` / `retrieval augmented generation`、`上下文窗口` / `context window`。

### 中英各搜一轮（重要）

用户用中文问，但缓存里的视频可能是英文（反之亦然）。中文分词是 CJK bigram，不会自动匹配英文原文：

- 第一轮：用用户语言的关键词；
- 第二轮：换成另一语言的关键词（意思是同一个术语，不是字面翻译）；
- 第三轮：换同义词 / 上位词 / 下位词 / 相关概念（`pricing` → `pricing model`、`billing`、`token 收费`；`context window` → `context length`、`上下文长度`）。

每轮只换 1–2 个词，观察 `resultCount` 与结果相关性，不要一次堆一堆词。

### 用参数缩小或扩大范围

| 参数 | 什么时候用 |
|---|---|
| `query` | 必填，1–200 字符，中英混合都行 |
| `video` | 用户说得清是哪个视频（标题/频道/你已定位到 videoId）时，在该视频内搜多个词；也可以用来验证「这条视频里有没有提过 X」 |
| `since` | 用户说「最近看的」「上个月之后抓的」→ 传 `YYYY-MM-DD`。**注意语义**：它按缓存的**抓取时间** `fetchedAt` 过滤，不是视频发布时间，向用户说明这一点 |
| `limit` | 默认 8，1–20；传大于 20 按 20 处理。要更全的候选先 `limit=20` 再人工筛 |
| `context` | 默认 1（前后各 1 段，每段 ≤200 字符）；片段太短、判断不了上下文时用 `context=2`，只想要命中句就用 `context=0` |

## 第二步：读结果

`tube_search` 只搜**本地缓存**（用户以前 `tube_transcript` 过的视频），不是全网搜索。返回里重点看：

- `scannedVideos` / `scannedSegments` / `resultCount` / `matchedVideos`：本次检索覆盖了多大范围、命中多少——**这个范围要写进回答里**；
- 每条 `results[]`：`videoId`、`title`、`channel`、`url`（watch 链接）、`startSeconds`、`timestamp`（分钟不补零，如 `12:34`）、`link`（`https://youtu.be/<id>?t=<sec>`）、`text`（命中段落原文，命中词附近截断）、`score`、`matchedTerms`、`before` / `after`；
- 若返回带 `truncated: true`：说明缓存视频超过 500 个，只扫描了最近抓取的 500 个，必须在综述里注明覆盖范围不是全集；
- 若返回带 `skippedCacheFiles`（>0）：有损坏的缓存文件被跳过，回答里可以提一句「有 N 个缓存损坏，可能覆盖不全」；
- 若 `matchedTerms` 只命中了泛词（the、视频、一个），说明关键词质量一般，换词。

**引用直接使用工具返回的 `link` 与 `timestamp`**，不要自己拼；`link` 的秒数与 `timestamp` 一致，双引用写成 `[12:34](https://youtu.be/<videoId>?t=754)`。

## 第三步：按需核实（不要只凭片段下结论）

搜索结果是片段，不是完整上下文。出现下面情况时展开全文核实：

- 要把这段当「金句/明确立场」引用；
- 片段在 `before`/`after` 里语义反转（「但是」「不过」在后半句）；
- 多条结果互相矛盾，需要看谁在什么语境下说的；
- 用户问的是「他到底怎么做的/完整方法」而不是一句观点。

核实方法：`tube_search` 的渲染文本末尾会给出**缓存目录**，直接用 `read` 读 `<缓存目录>/<videoId>.md` 打开该视频全文；或者调 `tube_transcript({ video: "<videoId>" })` 拿 `transcriptPath`（缓存命中，秒回）再 `read`。定位用 `grep` 搜命中词或时间戳前缀，再读前后段落。核实后发现搜索结果片段会误导，如实说明，不要硬用。

## 第 3.5 步：主题综述先拿底稿 —— 调 `tube_synthesis`

当用户不只是「随口问问」，而是要**存档 / 发文章 / 做一篇完整的主题综述**时，不要手工跑很多轮 `tube_search` 再抄链接：调一次 `tube_synthesis`，让它把「多轮检索 → 按视频分组 → 去重排序 → 生成带引用的证据底稿」都算好，你只负责基于底稿写综述。需要存档时还可以直接落盘。

### 参数怎么给

| 参数 | 怎么给 |
|---|---|
| `query` | 必填，1–200 字符。最核心的那个主题词（用户原话里的主题） |
| `queries` | 可选，额外 0–6 个检索词，与 `query` 合并去重。**建议一共给 2–4 个**：中英各一 + 1–2 个同义词/缩写（如 `大模型训练成本` / `scaling laws` / `training compute cost`）；不是越多越好，4 个以内最稳 |
| `video` / `since` | 可选，语义同 `tube_search`（单视频限定 / 按缓存抓取时间 `fetchedAt` 过滤） |
| `limitPerVideo` | 可选，1–8，默认 4。每个视频留几条证据；先默认，某个视频观点特别多再调大 |
| `maxVideos` | 可选，1–10，默认 10。底稿覆盖多少个视频；主题宽泛时保持 10，聚焦时调小 |
| `dir` | 可选，**绝对路径**。给了就当场把底稿落盘成带 frontmatter 的 Markdown（module=knowledge、sources=命中视频、文末来源、更新 index.md）；文件名用 query 生成，`title` 只改 frontmatter 标题。用户说「存下来 / 存成文章 / 放进知识库」时才传 |
| `title` | 可选，落盘时的标题 |

调用示例：

```js
tube_synthesis({
  query: "大模型训练成本",
  queries: ["scaling laws", "training compute cost"],
  limitPerVideo: 4,
  maxVideos: 10
})
```

### 返回什么、怎么用

- `videos[]`：按视频分组（按命中数降序），每个视频 `{ videoId, title, channel, url, durationSeconds, hits[] }`，`hits` 组内按时间升序，每条 `{ timestamp, startSeconds, link, text }`；
- `coverage`：`{ hitVideos, zeroHitVideos, totalHits, queriedTerms }`——写「共识 / 分歧 / 覆盖缺口」时直接用它，尤其 `zeroHitVideos`（缓存里有、但本主题没命中的视频）；
- `scannedVideos` / `scannedSegments`：检索范围，写进综述开头；
- `markdown`：工具生成的**证据底稿**（检索范围 + 按视频分组的证据 + 未命中视频 + 检索覆盖 + 下一步）；这是你的证据表，不是最终成稿；
- 传了 `dir` 时还有 `path` / `indexpath` / `bytes`：底稿已落盘，把路径告诉用户；**最终成稿再用 `tube_export`，不要重复导出底稿**；
- 相同输入重复调用结果稳定（导出文件名的时间戳除外）：可以放心换 `queries` 组合重跑对比，不用担心结果漂移。

### 底稿链接硬规则（最重要）

**底稿 `markdown` 里的每一条 `[MM:SS](https://youtu.be/<id>?t=<sec>)` 都是工具算好的，必须原样使用**：不改写、不重拼、不调整秒数、不改大小写、不按印象替换 id。写综述时把链接连同 `timestamp` 一起复制过去；需要额外证据就回到 `tube_search` / `tube_transcript` 拿字段，绝不自造链接（见后面「链接与 videoId 硬规则」）。

### 基于底稿写综述

底稿是证据表，不是成稿。按第四步 B 的模板重新组织：

- 一句话结论：基于全部 `hits` 归纳，不要逐条复述；
- 观点汇总：按**主题/观点**分组，同一观点多视频出现时合并 + 交叉印证；每条带底稿里原样的双引用；
- 共识与分歧：至少 2 个视频支持才算共识；分歧写明各自出处；
- 覆盖不到的地方：用 `coverage.zeroHitVideos` 和底稿里缺的主题，如实写「缓存中的 X 个视频未涉及本主题」；
- 相关视频清单：只用 `videos[]` 里有工具返回字段的视频与链接（遵守链接硬规则）。

### 无命中怎么办

| 情况 | 你该做什么 |
|---|---|
| 无命中、没传 `dir` | 工具正常返回空底稿 + `zeroHitVideos` 为全部缓存视频。先换检索词重调（同义 / 中英 / 上位词，2–3 轮），仍空才如实说「缓存里没有关于 X 的证据」，并说明扫描范围；不要直接说「你没看过」 |
| 无命中、传了 `dir` | 工具会报错「本次检索无命中，未导出」——这是预期行为：换词重调，或去掉 `dir` 先看有没有证据；不要假装导出成功，也不要自己写文件补底稿 |
| 报「导出失败：写文件时出错」 | `dir` 不是绝对路径、目录不存在或没有写权限。检查路径/权限后重试，或去掉 `dir` 先拿底稿 |
| 底稿很稀疏（只有 1–2 条） | 说明覆盖有限；补搜相关概念，或建议用户先抓取更多相关视频（`tube_transcript`）再重跑 |

## 第四步：组织输出

### 链接与 videoId 硬规则（模式 0 特有，违反即返工）

1. **回答里出现的任何 YouTube 链接 / videoId，只能来自工具返回字段**：`tube_search` 结果里的 `url`（watch 链接）或 `link`（带时间戳链接），`tube_synthesis` 的 `videos[].url` / `hits[].link`，或 `tube_transcript` 返回的 `videoId`。**禁止凭记忆手写、也不要照着缓存目录文件名手打 videoId**——YouTube ID 大小写敏感（`AbCdEf12345` 不等于 `abcdef12345`），错一个字符链接就打不开。
2. **补充信息宁缺勿错**：「相关视频清单」这类没有被工具返回字段支撑的补充内容，只写标题 + 频道、不写链接，或者干脆不列。想给链接，该视频必须在 `tube_search` / `tube_synthesis` 结果里出现过（直接用返回的 `url` / `link`），或者你手上有它的 URL/ID 且用 `tube_transcript` 验证过（以返回的 `videoId` 为准）；做不到就不给链接。

### A. 找回某条视频（「我记得有个视频说…」）

```markdown
找到了，应该是这条：

**{标题}** · {频道} · {时长} · {工具返回的 `url`（或由 `tube_transcript` 返回的 `videoId` 拼出的链接）}
> [12:34](https://youtu.be/<videoId>?t=754) {命中的原文片段}
> 上下文：{before / after 一句话说明}

要继续的话：① 我给这条视频做完整概览；② 只把相关段落整理成笔记。
```

如果有 2–3 个候选，列成小表格（标题 / 频道 / 命中片段 / 链接），让用户挑，不要替用户拍板。

### B. 主题综述（「看过的视频里关于 X 的观点」）

```markdown
# 主题综述｜{主题}

> 检索范围：本地缓存 {scannedVideos} 个视频、{scannedSegments} 个段落；命中 {resultCount} 条，涉及 {matchedVideos} 个视频
> 检索词：`{词 1}`、`{词 2}`、`{词 3}`（共 {N} 轮）

## 一句话结论
> {跨视频看下来最核心的判断，没有就明说「证据不足以形成结论」}

## 观点汇总
### {观点/子主题 1}
- {哪条视频、谁怎么说} — [12:34](https://youtu.be/<id>?t=754)
  > {原文片段}
- 交叉印证：{另一条视频里类似的说法} — [3:20](https://youtu.be/<id2>?t=200)

### {观点/子主题 2}
……

## 共识与分歧
- 共识：{至少 2 个视频都提到的}
- 分歧：{说法不一致的地方，各自出处}

## 覆盖不到的地方
- 缓存里的视频没有涉及……（如实写；不要用常识补成视频观点）

## 相关视频清单
| 视频 | 频道 | 命中条数 | 链接（只填工具返回的） |
|---|---|---|---|
| {标题} | {频道} | {n} | {`url` / `link`；没有工具字段支撑就填 —} |
```

用 `tube_synthesis` 底稿写综述时，把上面的占位符换成工具返回的数字：检索范围用 `scannedVideos` / `scannedSegments`，命中数用 `coverage.totalHits` / `coverage.hitVideos`，检索词用 `coverage.queriedTerms`，清单里的「命中条数」用该视频 `hits` 的条数。

「相关视频清单」也受上面的链接硬规则约束：只有 `tube_search` / `tube_synthesis` 结果里出现过（或 `tube_transcript` 验证过）的视频才能填链接；检索命中 0 条、只是你知道它在缓存里的视频，只写标题 + 频道、链接列填 `—`，或者干脆不列。宁可少列一条，也不要给一个打不开的链接。

组织原则：

- 用户要「汇总观点」就按**主题/观点**组织；用户要「找视频」就按**视频**组织；
- 同一观点多视频重复时合并，只保留信息量最大的一处 + 交叉印证；
- 每条来自视频的结论必须带双引用；跨视频时链接的 `videoId` 要和内容对应，**不要串 id**；链接只能来自工具返回字段（见上面「链接与 videoId 硬规则」）。
- 视频没说的不写；没找到就说没找到；
- 输出语言默认中文（照 SKILL.md 的语言策略），原文片段保留视频原语言，需要时附一句译文。

## 第五步：结果不足 / 为空怎么办

| 情况 | 你该做什么 |
|---|---|
| 工具报「缓存为空」 | 明说本地还没有抓过任何视频；请用户给 YouTube 链接，先用 `tube_transcript` 抓取，再检索 |
| `video` 指定的视频不在缓存 | 工具会报错并提示先用 `tube_transcript({ video: "<id>" })` 抓取；照做后再搜，或去掉 `video` 搜全库 |
| `resultCount = 0` | 先别急着说「没有」：① 换同义词/另一语言再搜一轮；② 放宽 `since`、去掉 `video` 限定；③ 换上位词或相关概念；最多 2–3 轮后仍为空，才说「在你已缓存的 N 个视频里没找到关于 X 的内容」，并说明扫描范围 |
| `tube_synthesis` 报「本次检索无命中，未导出」 | 换检索词重调，或去掉 `dir` 先确认有没有证据；详见第 3.5 步「无命中怎么办」 |
| 结果少或看起来不相关 | 换关键词而不是加参数；拆成几个小主题分别搜；必要时搜相关术语 |
| 用户想搜**没抓过**的视频 | 明确检索只覆盖本地缓存；需要先抓取，或者改用 `web_search` 全网搜（要说明这是全网结果，不是他看过的视频） |
| `since` 把结果过滤没了 | 说明 `since` 按抓取时间过滤；确认时间范围，或去掉 `since` 重试 |
| `truncated: true` | 在回答里注明只扫描了最近抓取的 500 个视频，覆盖范围不是全集 |

## 第六步：需要存档时

分两种，别搞反顺序：

- **主题综述 / 发文章 / 要证据底稿**：先走第 3.5 步 `tube_synthesis`；要落盘就把 `dir` 传绝对路径（底稿带 frontmatter，module=knowledge）。底稿落盘后，用户要的**最终成稿**再用 `tube_export`，不要重复导出底稿。
- **基于综述正文的成稿**（含从底稿重写出来的文章）→ 调 `tube_export`：
  - `module`：观点/行业类主题综述用 `insights`；学习笔记/知识卡片式汇总用 `knowledge`；
  - `videos`：本次综述**实际引用到的**视频 ID 列表（来自 `tube_synthesis` 的 `videos[]` 或 `tube_search` 的 results），最多 10 个。超过 10 个时只挂最相关的 10 个，并在正文开头注明「来源视频较多，导出只关联了最相关的 10 个」，或按主题拆成多份导出；
  - `markdown`：第四步 B 的综述正文（基于底稿重新组织过的成稿，不是底稿原文），不要再包 frontmatter/来源区块；
  - `title`：建议 `主题综述：{主题}`；`dir` 用绝对路径；`notes` 只在用户给了原始笔记时传。

导出后把返回的 `path` 告诉用户。

## 交付前自查

- 是否写清了「检索的是本地缓存的 N 个视频、M 个段落」，而不是让用户以为搜了全网？
- 有没有做中英/同义词的补充检索？`resultCount=0` 时是否换过词再说没有？
- 每条结论是否都有 `[MM:SS]` + `https://youtu.be/<videoId>?t=<sec>` 双引用，且链接的 id 与内容对应？
- 引用原文是否来自工具结果或核实过的转录，而不是凭印象补的？
- 只凭片段下结论了吗？该核实（语境界词、矛盾、完整方法）的核实了吗？
- 视频没提到的是否如实留在「覆盖不到的地方」，没有拿自己的知识冒充视频观点？
- 需要存档时，`videos` 是否只放实际引用的视频（≤10），module 选对了吗？
- **所有链接的 `videoId` 都来自工具返回字段吗**（`tube_search` 的 `url` / `link`，`tube_synthesis` 的 `videos[].url` / `hits[].link`，或 `tube_transcript` 的 `videoId`）？有没有凭记忆手打、大小写写错？「相关视频清单」里没有工具字段支撑的链接是否已删掉或改成「标题 + 频道」？
- 主题综述 / 存档类需求是否先用了 `tube_synthesis` 拿底稿？底稿里的链接是否**原样使用**（没有重拼、改秒数、改大小写）？
- `coverage.zeroHitVideos` 是否写进「覆盖不到的地方」？无命中时是否先换词、再如实说明，而不是凭印象编或直接说「你没看过」？
