# Recall：回忆 / 检索 / 主题综述

> **何时读我**：用户指的是**以前抓过、看过**的视频，而不是贴一条新链接给你。典型说法：「我以前看过的视频里，关于 X 都是怎么说的」「我记得有个视频说……帮我找出来」「把我看过的视频里关于 X 的观点汇总一下」「搜一下我的视频库/我抓过的视频」「做了这么久研究，帮我把 XX 主题整理成一篇综述」。
>
> **上游来源**：0.2.0 新增，无上游对应。工具契约见 0.2.0 功能契约的 F1（`tube_search`，签名已冻结；该契约文档在插件开发仓库，不在本 skill 目录内）。

## 先分清三种意图

| 用户说的 | 你要做的 |
|---|---|
| 「我记得有个视频说……」想找回**某一条视频** | 检索定位视频 → 给视频卡片（标题/频道/时长/链接 + 命中片段），确认是不是它；要找的是视频本身，别急着写综述 |
| 「看过的视频里关于 X 怎么说」要**观点汇总** | 检索 → 按视频/按观点组织 → 带双引用的综述（本文件主流程） |
| 贴了新链接、或要分析一条指定视频 | 不走检索，回到 SKILL.md 的四步工作流（overview / intel / insights 等） |

## 第一步：把用户的话变成检索词

`tube_search` 的 `query` 是关键词检索（BM25 + 连续短语加成），不是语义搜索。**口语要翻译成视频里可能出现的词**：

- 去掉口语外壳：「我记得/有个视频/以前/好像/帮我找找」不是检索词；
- 抽实体 + 术语 + 动作：人名、产品名、缩写、主题词；
- 一次 2–5 个关键词，最多 200 字符；不要整句丢进去（query 越长，词越稀释）；
- **视频里怎么说就怎么搜**：视频是英文就搜英文，是中文就搜中文；用视频里可能的原话短语（连续短语有加成）；
- 缩写与全称都试：`LLM` / `large language model`、`RAG` / `retrieval augmented generation`、`上下文窗口` / `context window`。

### 中英各搜一轮（重要）

用户用中文问，但缓存里的视频可能是英文（反之亦然）。中文分词是 CJK bigram，不会自动匹配英文原文：

- 第一轮：用用户语言的关键词；
- 第二轮：换成另一语言的关键词（意思是同一个术语，不是字面翻译）；
- 第三轮：换同义词 / 上位词 / 下位词 / 相关概念（`pricing` → `pricing model`、`billing`、`token 收费`；`context window` → `context length`、`上下文长度`）。

每轮只换 1–2 个词，观察 `resultCount` 与结果相关性，不要一次堆一堆词。

### 用参数缩小或扩大范围

| 参数 | 什么时候用 |
|---|---|
| `query` | 必填，1–200 字符，中英混合都行 |
| `video` | 用户说得清是哪个视频（标题/频道/你已定位到 videoId）时，在该视频内搜多个词；也可以用来验证「这条视频里有没有提过 X」 |
| `since` | 用户说「最近看的」「上个月之后抓的」→ 传 `YYYY-MM-DD`。**注意语义**：它按缓存的**抓取时间** `fetchedAt` 过滤，不是视频发布时间，向用户说明这一点 |
| `limit` | 默认 8，1–20；传大于 20 按 20 处理。要更全的候选先 `limit=20` 再人工筛 |
| `context` | 默认 1（前后各 1 段，每段 ≤200 字符）；片段太短、判断不了上下文时用 `context=2`，只想要命中句就用 `context=0` |

## 第二步：读结果

`tube_search` 只搜**本地缓存**（用户以前 `tube_transcript` 过的视频），不是全网搜索。返回里重点看：

- `scannedVideos` / `scannedSegments` / `resultCount` / `matchedVideos`：本次检索覆盖了多大范围、命中多少——**这个范围要写进回答里**；
- 每条 `results[]`：`videoId`、`title`、`channel`、`url`（watch 链接）、`startSeconds`、`timestamp`（分钟不补零，如 `12:34`）、`link`（`https://youtu.be/<id>?t=<sec>`）、`text`（命中段落原文，命中词附近截断）、`score`、`matchedTerms`、`before` / `after`；
- 若返回带 `truncated: true`：说明缓存视频超过 500 个，只扫描了最近抓取的 500 个，必须在综述里注明覆盖范围不是全集；
- 若返回带 `skippedCacheFiles`（>0）：有损坏的缓存文件被跳过，回答里可以提一句「有 N 个缓存损坏，可能覆盖不全」；
- 若 `matchedTerms` 只命中了泛词（the、视频、一个），说明关键词质量一般，换词。

**引用直接使用工具返回的 `link` 与 `timestamp`**，不要自己拼；`link` 的秒数与 `timestamp` 一致，双引用写成 `[12:34](https://youtu.be/<videoId>?t=754)`。

## 第三步：按需核实（不要只凭片段下结论）

搜索结果是片段，不是完整上下文。出现下面情况时展开全文核实：

- 要把这段当「金句/明确立场」引用；
- 片段在 `before`/`after` 里语义反转（「但是」「不过」在后半句）；
- 多条结果互相矛盾，需要看谁在什么语境下说的；
- 用户问的是「他到底怎么做的/完整方法」而不是一句观点。

核实方法：`tube_search` 的渲染文本末尾会给出**缓存目录**，直接用 `read` 读 `<缓存目录>/<videoId>.md` 打开该视频全文；或者调 `tube_transcript({ video: "<videoId>" })` 拿 `transcriptPath`（缓存命中，秒回）再 `read`。定位用 `grep` 搜命中词或时间戳前缀，再读前后段落。核实后发现搜索结果片段会误导，如实说明，不要硬用。

## 第四步：组织输出

### 链接与 videoId 硬规则（模式 0 特有，违反即返工）

1. **回答里出现的任何 YouTube 链接 / videoId，只能来自工具返回字段**：`tube_search` 结果里的 `url`（watch 链接）或 `link`（带时间戳链接），或 `tube_transcript` 返回的 `videoId`。**禁止凭记忆手写、也不要照着缓存目录文件名手打 videoId**——YouTube ID 大小写敏感（`AbCdEf12345` 不等于 `abcdef12345`），错一个字符链接就打不开。
2. **补充信息宁缺勿错**：「相关视频清单」这类没有被工具返回字段支撑的补充内容，只写标题 + 频道、不写链接，或者干脆不列。想给链接，该视频必须在 `tube_search` 结果里出现过（直接用返回的 `url` / `link`），或者你手上有它的 URL/ID 且用 `tube_transcript` 验证过（以返回的 `videoId` 为准）；做不到就不给链接。

### A. 找回某条视频（「我记得有个视频说…」）

```markdown
找到了，应该是这条：

**{标题}** · {频道} · {时长} · {工具返回的 `url`（或由 `tube_transcript` 返回的 `videoId` 拼出的链接）}
> [12:34](https://youtu.be/<videoId>?t=754) {命中的原文片段}
> 上下文：{before / after 一句话说明}

要继续的话：① 我给这条视频做完整概览；② 只把相关段落整理成笔记。
```

如果有 2–3 个候选，列成小表格（标题 / 频道 / 命中片段 / 链接），让用户挑，不要替用户拍板。

### B. 主题综述（「看过的视频里关于 X 的观点」）

```markdown
# 主题综述｜{主题}

> 检索范围：本地缓存 {scannedVideos} 个视频、{scannedSegments} 个段落；命中 {resultCount} 条，涉及 {matchedVideos} 个视频
> 检索词：`{词 1}`、`{词 2}`、`{词 3}`（共 {N} 轮）

## 一句话结论
> {跨视频看下来最核心的判断，没有就明说「证据不足以形成结论」}

## 观点汇总
### {观点/子主题 1}
- {哪条视频、谁怎么说} — [12:34](https://youtu.be/<id>?t=754)
  > {原文片段}
- 交叉印证：{另一条视频里类似的说法} — [3:20](https://youtu.be/<id2>?t=200)

### {观点/子主题 2}
……

## 共识与分歧
- 共识：{至少 2 个视频都提到的}
- 分歧：{说法不一致的地方，各自出处}

## 覆盖不到的地方
- 缓存里的视频没有涉及……（如实写；不要用常识补成视频观点）

## 相关视频清单
| 视频 | 频道 | 命中条数 | 链接（只填工具返回的） |
|---|---|---|---|
| {标题} | {频道} | {n} | {`url` / `link`；没有工具字段支撑就填 —} |
```

「相关视频清单」也受上面的链接硬规则约束：只有 `tube_search` 结果里出现过（或 `tube_transcript` 验证过）的视频才能填链接；检索命中 0 条、只是你知道它在缓存里的视频，只写标题 + 频道、链接列填 `—`，或者干脆不列。宁可少列一条，也不要给一个打不开的链接。

组织原则：

- 用户要「汇总观点」就按**主题/观点**组织；用户要「找视频」就按**视频**组织；
- 同一观点多视频重复时合并，只保留信息量最大的一处 + 交叉印证；
- 每条来自视频的结论必须带双引用；跨视频时链接的 `videoId` 要和内容对应，**不要串 id**；链接只能来自工具返回字段（见上面「链接与 videoId 硬规则」）。
- 视频没说的不写；没找到就说没找到；
- 输出语言默认中文（照 SKILL.md 的语言策略），原文片段保留视频原语言，需要时附一句译文。

## 第五步：结果不足 / 为空怎么办

| 情况 | 你该做什么 |
|---|---|
| 工具报「缓存为空」 | 明说本地还没有抓过任何视频；请用户给 YouTube 链接，先用 `tube_transcript` 抓取，再检索 |
| `video` 指定的视频不在缓存 | 工具会报错并提示先用 `tube_transcript({ video: "<id>" })` 抓取；照做后再搜，或去掉 `video` 搜全库 |
| `resultCount = 0` | 先别急着说「没有」：① 换同义词/另一语言再搜一轮；② 放宽 `since`、去掉 `video` 限定；③ 换上位词或相关概念；最多 2–3 轮后仍为空，才说「在你已缓存的 N 个视频里没找到关于 X 的内容」，并说明扫描范围 |
| 结果少或看起来不相关 | 换关键词而不是加参数；拆成几个小主题分别搜；必要时搜相关术语 |
| 用户想搜**没抓过**的视频 | 明确检索只覆盖本地缓存；需要先抓取，或者改用 `web_search` 全网搜（要说明这是全网结果，不是他看过的视频） |
| `since` 把结果过滤没了 | 说明 `since` 按抓取时间过滤；确认时间范围，或去掉 `since` 重试 |
| `truncated: true` | 在回答里注明只扫描了最近抓取的 500 个视频，覆盖范围不是全集 |

## 第六步：需要存档时

用户说「整理成文章/存下来/放进知识库」时调 `tube_export`：

- `module`：观点/行业类主题综述用 `insights`；学习笔记/知识卡片式汇总用 `knowledge`；
- `videos`：本次综述**实际引用到的**视频 ID 列表，最多 10 个。超过 10 个时只挂最相关的 10 个，并在正文开头注明「来源视频较多，导出只关联了最相关的 10 个」，或按主题拆成多份导出；
- `markdown`：本文件第四步的综述正文，不要再包 frontmatter/来源区块；
- `title`：建议 `主题综述：{主题}`；`dir` 用绝对路径；`notes` 只在用户给了原始笔记时传。

导出后把返回的 `path` 告诉用户。

## 交付前自查

- 是否写清了「检索的是本地缓存的 N 个视频、M 个段落」，而不是让用户以为搜了全网？
- 有没有做中英/同义词的补充检索？`resultCount=0` 时是否换过词再说没有？
- 每条结论是否都有 `[MM:SS]` + `https://youtu.be/<videoId>?t=<sec>` 双引用，且链接的 id 与内容对应？
- 引用原文是否来自工具结果或核实过的转录，而不是凭印象补的？
- 只凭片段下结论了吗？该核实（语境界词、矛盾、完整方法）的核实了吗？
- 视频没提到的是否如实留在「覆盖不到的地方」，没有拿自己的知识冒充视频观点？
- 需要存档时，`videos` 是否只放实际引用的视频（≤10），module 选对了吗？
- **所有链接的 `videoId` 都来自工具返回字段吗**（`tube_search` 的 `url` / `link`，或 `tube_transcript` 的 `videoId`）？有没有凭记忆手打、大小写写错？「相关视频清单」里没有工具字段支撑的链接是否已删掉或改成「标题 + 频道」？
